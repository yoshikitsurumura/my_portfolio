# お問い合わせフォーム（GAS）セットアップ手順

サイトのお問い合わせフォームは、Google Apps Script のウェブアプリに POST して
`crane7112@gmail.com` に通知メールを送る構成になっている。

| ファイル | 役割 |
| --- | --- |
| `gas_contact_form.js` | GAS 側の処理（通知メール送信・スプレッドシート記録） |
| `../../assets/js/contact-form.js` | サイト側の送信処理（サンクスページへの遷移・二重送信防止） |
| `../../config/gas_links.md` | 管理用リンクとデプロイURL |

---

## メールが届かなくなったときの切り分け

上から順に確認する。ほとんどの場合 1 か 2 が原因。

### 1. デプロイが最新のコードになっているか（最頻出）

GAS は **コードを保存しただけではウェブアプリに反映されない**。
`/exec` の URL は「デプロイした時点のコード」を実行し続ける。

1. スクリプトエディタ右上の **デプロイ → デプロイを管理**
2. 対象のデプロイの **鉛筆アイコン（編集）**
3. **バージョン** を `新バージョン` に変更
4. **デプロイ** をクリック

URL は変わらないので、サイト側の修正は不要。

### 2. ウェブアプリの公開設定

同じ「デプロイを編集」画面で以下になっていること。

- **次のユーザーとして実行**: 自分（`crane7112@gmail.com`）
- **アクセスできるユーザー**: **全員**

`全員（匿名ユーザーを含む）` 相当になっていないと、サイト訪問者の送信が
Google のログイン画面にリダイレクトされて届かない。

### 3. URL が生きているか

`config/gas_links.md` の実行URLを**ブラウザでそのまま開く**。

- `{"status":"ok", ...}` が表示される → デプロイと公開設定は正常。3 以降へ
- ログイン画面になる → 上の 2 が原因
- 「スクリプト関数が見つかりません: doGet」 → 古いコードのまま。上の 1 が原因

### 4. 権限（承認）が済んでいるか

エディタで `testEmailOnly` を選んで **実行**。
初回は承認画面が出るので、`詳細` → `（プロジェクト名）に移動` → `許可` まで進める。

- 実行ログに「送信しました。残りの送信可能数: …」→ メール送信は正常
- 残りの送信可能数が `0` → 1 日の上限（無料アカウントは 100 通/日）。翌日まで待つ

### 5. 迷惑メールフォルダ

自動送信メールは Gmail の「迷惑メール」「プロモーション」に入ることがある。
`from:me 件名:CraneAI` で検索して確認する。

## 初回セットアップ

1. https://script.google.com で新規プロジェクトを作成
2. `gas_contact_form.js` の中身を貼り付けて保存
3. `testEmailOnly` を実行して承認を済ませる（上の 4）
4. **デプロイ → 新しいデプロイ → 種類の選択: ウェブアプリ**
   - 次のユーザーとして実行: 自分
   - アクセスできるユーザー: 全員
5. 発行された `/exec` URL を、以下 4 ファイルの `<form action="...">` に設定
   - `index.html`
   - `pages/ai-chatbot-development.html`
   - `pages/web-app-development.html`
   - `pages/business-automation-tool.html`
6. URL を `config/gas_links.md` にも記録しておく

## スプレッドシートへの記録（任意）

未設定でも通知メールは届く。記録を残したい場合のみ設定する。

**方法 A: スクリプトプロパティで指定（推奨）**

1. 記録用スプレッドシートを作成し、URL の `/d/` と `/edit` の間の ID をコピー
   `https://docs.google.com/spreadsheets/d/【ここがID】/edit`
2. エディタの **プロジェクトの設定 → スクリプト プロパティ → プロパティを追加**
   - プロパティ: `SHEET_ID`
   - 値: コピーした ID
3. `testSheetOnly` を実行して、ログに接続先が出れば成功

**方法 B: コードに直接書く**

`gas_contact_form.js` の `CONFIG.SHEET_ID` に ID を書いてデプロイし直す。

シートと見出し行は初回送信時に自動作成される。

## 動作確認用の関数

エディタ上部のプルダウンから選んで実行し、`実行ログ` を見る。

| 関数 | 内容 |
| --- | --- |
| `testEmailOnly` | メール送信だけを試す。権限まわりの切り分けに使う |
| `testSheetOnly` | スプレッドシート接続だけを試す |
| `testDoPost` | 実際の送信と同じ流れを通す（メール＋シート） |

## 設計メモ

- **通知メールを最初に送る。** スプレッドシート記録はその後に、独立した
  `try` で実行する。以前はシート保存が先だったため、スプレッドシートが
  未接続のスタンドアロンプロジェクトでは `getActiveSpreadsheet()` が `null` を返し、
  そこで例外になってメールが 1 通も送られなかった。
- **`GmailApp` ではなく `MailApp` を使う。** 必要な認可スコープが少なく、
  通知メールの送信用途ではこちらの方が確実に動く。
- **`replyTo` はアドレスが正しいときだけ付ける。** 不正な値を渡すと
  送信そのものが例外で失敗するため。
- **受信内容は HTML エスケープしてからメール本文に入れる。**
  フォームは公開エンドポイントなので、タグを含む文字列が送られてくる前提で扱う。
- **サンクスページへの遷移はサイト側で行う。** GAS の出力はサンドボックス
  iframe に描画されるため、GAS 側からの遷移はブラウザにブロックされることがある。
  `assets/js/contact-form.js` が非表示 iframe に送信してレスポンスを待ち、
  自前で遷移する。JavaScript が無効な環境では通常のフォーム送信にフォールバックし、
  GAS が返すページの手動リンクからサイトに戻れる。
